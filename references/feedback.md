# 反馈与持续迭代

这是每次调用时维护的本地记忆流程，不是后台自动监听。由 AI 处理自然聊天和获授权资料，不让用户填表。

## 先分清反馈是什么

| 类型 | 可以驱动什么 | 不能推出什么 |
|---|---|---|
| 用户编辑意见 | 口吻、长度、画风、主题权重 | 所有未来课程的永久规则，除非明确说今后都如此 |
| 课程事实更新 | 本门课新日期、受众、模块、权益 | 自动改写其他课档案 |
| 学员自述 | 有来源的使用体验/自述变化 | 已独立验证的经营收益 |
| 可核实结果 | 对应样本、周期、口径下的事实 | 因果归于课程、普遍有效、保证复现 |
| AI 推测 | 待测试选题或建议 | 学员证言、用户决定 |

客户反馈的来源、时间、对应课程和可公开范围保存在私有证据记录里。公开正文可以省略具体日期和人名。原文证据不要因公开稿润色而覆盖。没有公开使用依据时优先匿名、归纳非敏感事实，涉及客户身份/敏感经营数据先确定授权。

## 存储与应用

1. 为每个反馈创建稳定 ID，记录 `course_id`、类型、作用域（本批/本课程/跨课程）、来源引用、实际原话或脱敏摘录、明确行动、状态和记录时间。
2. 写到项目 `feedback.jsonl`；原始证据保存在私有 `evidence/`。不要把私人原话写进本技能目录。
3. 当新意见明确替代同课程同规则，追加记录并用 `supersedes` 指向旧 ID；不删旧记录。当前规则取未被替代的有效记录，来源冲突保留待核。
4. 更新 `course-profile.json` 中的风格覆盖项或已核实事实，并记录来源。跨课程偏好只在用户明确表达长期范围时保存为独立共享风格配置；不能仅凭一次满意或沉默推广。
5. 把本轮错误改成一个回归例子。例如「面向老板但只罗列功能」→「每条必须有工作卡点及课程动作」。回读修改后的稿件，记录改了什么、依据是什么、实际检查了什么。
6. 下一批读取这些有效规则、旧选题和已认可样张，避免用户反复解释。

轻量记录可由 AI 创建 JSON 后执行 `scripts/campaign.py record-feedback --workspace <目录> --file <JSON>`；字段见 `workspace.md`。脚本只检查记录结构，不证明原话真实、授权充分或新理解正确，仍需 AI 核对原来源。

## 更新技能本体的边界

一般反馈先更新课程档案，不直接改 SKILL.md。本课程已经授权随技能分发：可共享的课程变化、脱敏反馈归纳和编辑规则，同步更新 `courses/ai-commerce-workshop/` 中对应文件；不要求用户另行整理背景包。原始私人记录仍不进仓库。用户明确要优化本技能，或在该授权下发现可迁移规则时：保存旧版本 → 只改相关规则 → 跑典型课程/换课程/缺信息/证言冲突回归 → 更新版本说明并重新打包。不要把失败产物直接当新样张。

效果复盘可看询问、报名、成交等实际数据，但保留渠道、时间和归因边界。没有数据时写「尚未验证转化效果」，不要把用户觉得好、发送成功、AI 评分高当成交证据。
